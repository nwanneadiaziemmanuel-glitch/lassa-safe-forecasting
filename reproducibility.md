# Reproducibility

## V1.1 release status

This repository contains a corrected, leakage-controlled **V1.1 core forecasting implementation** plus an explicitly separated archive of the original V1 analytical outputs.

The separation is deliberate. The original V1 tables were frozen before implementation-level reconciliation. They are retained for scientific provenance rather than silently overwritten.

## Reproduce the core analysis

From the repository root:

```bash
python -m pip install -r requirements.txt
python -m pytest -q
python -m src.run_analysis
```

The final command writes core outputs to:

```text
results/v1_1_core/
├── annual_totals.csv
├── seasonality_by_epi_week.csv
├── audit_summary.json
├── feature_matrix.csv
└── forecast_reproduction.csv
```

## What the core runner reproduces

The V1.1 runner reproduces:

- the dataset audit;
- the feature matrix;
- leakage-controlled 1–4 week Gradient Boosting forecasts; and
- MAE/RMSE for the four evaluation years.

The code uses an expanding year-based temporal holdout and prevents training targets from crossing into the evaluation year.

## Archived V1 outputs

The original V1 outputs are stored under:

```text
results/archive_v1/
figures/archive_v1/
```

They include the original model comparison, augmentation, uncertainty, robustness, failure-analysis and synthetic-fidelity tables and their corresponding figures.

These archived outputs are **not represented as being regenerated by the V1.1 core runner**.

## Reproducibility principle

A result is considered reproducible only when the repository identifies the data, code, environment and analytical version needed to recreate it. Where an historical result cannot currently be recreated by the corrected implementation, it remains explicitly labelled as an archived V1 result rather than being silently replaced.
